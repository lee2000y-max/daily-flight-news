# P3 실험: 구글 플라이트 판매처별 가격(예약 옵션) — 2026-11-03

## 방법
- `probe_booking.py` (진단 워크플로 `mode=booking`). GitHub Actions 서버의 실제 Chromium으로 구글 플라이트를 열고,
  화면이 보여 주는 대로 가는 편 첫 줄 → 오는 편 첫 줄 → "Booking options"를 읽었다. 차단·CAPTCHA 화면이 나오면 중단(우회 없음).
- 대상: 그날 1위 일정 3건(옌타이·오사카·방콕).

- 세 노선 모두 차단 없이 예약 옵션까지 열렸다(노선당 약 15초).
- 판매처 수는 1~2곳뿐이었다. 저가항공 직항은 항공사 직판만 나오는 경우가 많아 "최저~최고" 범위가 의미 있는 노선은 일부일 것으로 보인다.
- 덤으로 확인된 것: 예약 옵션 화면에 위탁 수하물 정보("1st checked bag free")와 구글의 "보통 가격 범위"(방콕 ₩435,000~700,000)가 함께 나온다.
- 카드 가격과 구글 화면 가격이 3건 모두 일치(오사카는 26원 차이). P0 통과 조건의 가격 대조 근거로도 쓸 수 있다.

## 정식 도입 시 고려
- 매일 56개 도시 × 약 15초 = 약 15분(8묶음이면 묶음당 2분 남짓) 추가. 브라우저 자동화라 구글 쪽 제한이 생길 위험은 API 조회보다 크다.
- 화면 구조가 바뀌면 깨진다(텍스트 "Book with", "Booking options"에 의존).
- 도입 여부는 사용자 결정 사항으로 남긴다(PLAN D5: P3에서 실험).
